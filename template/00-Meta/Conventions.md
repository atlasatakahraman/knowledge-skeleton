# Conventions

The vault schema. The hooks, the `/brain` skill and `brain-doctor` all assume it.

## Frontmatter

Every note. `README.md`, `CLAUDE.md`, `AGENTS.md` and `LICENSE*` are the only exemptions.

```yaml
---
type: identity|rules|moc|repo|architecture|decision|session|plan|doc|usage|commit|commits|task|person
project: <the repo's remote name in lowercase> | knowledge
tags: [topic, topic]
created: 2026-01-01
updated: 2026-01-02
status: active | draft | superseded | in-progress | complete | done | legacy
---
```

`type` and `created` are required: `brain-doctor`'s `frontmatter` check and the write-time check in
`brain-reindex` fail without them. `project` is required for anything repo-scoped; the vault itself
is `knowledge`. `updated` changes on every edit. A `status: superseded` note keeps a link to what
replaced it.

`commit` is one per-commit note, written by `brain-commit`; `commits` is its generated month index.
`moc` is a map of content, hand-written or generated by `brain-hubs`.

## Naming

- **Files:** kebab-case. `retry-backoff.md`, not `Retry Backoff.md`. A repo's folder note takes its
  remote's exact casing (`My-App.md`).
- **MOCs:** `00-MOC-<Scope>.md`, one per folder. Always sorts first.
- **Every basename is unique across the vault.** Obsidian and graphify resolve `[[name]]` by
  filename, so two notes with one name make every link to either ambiguous. That is why there is no
  `about.md`, `plan.md` or `index.md` anywhere.
- **Folder notes:** a folder's main note is `<Folder>/<Folder>.md` (`10-Repos/My-App/My-App.md`,
  `40-Plans/<slug>/<slug>.md`). Other notes in the folder get specific names, never generic ones.
- **Repo names are the GitHub remote's exact casing**, in `10-Repos/`, `60-Decisions/Repos/` and
  `80-Assets/Repos/` alike. One name, three places, no aliases.
- **Plans:** every plan lives in the vault, one-repo plans included. One folder each:
  `40-Plans/<YYYY-MM-DD>-<slug>/` holding `<slug>.md` (diagnosis + stages), and optionally
  `<slug>-spec.md`, `<slug>-implementation.md`, `stages/`, `evidence/`.
- **Decisions (ADRs):** `60-Decisions/Repos/<Remote-Name>/<NNNN>-<slug>.md` for one repo;
  `60-Decisions/Identity/<NNNN>-<slug>.md` for the vault, its hooks, or how the agent behaves.
  `<NNNN>` is a per-folder sequence from `0001`. Never inside a checkout.
- **Records** (daily notes, commit notes) are reached through a generated index (`00-MOC-Sessions`,
  `commits-YYYY-MM`) that is itself at most 2 hops from the root MOC. Never edit a generated index by
  hand; `brain-hubs` and `brain-commit` rewrite them.
- **Generated month files** share one scheme: `commits-YYYY-MM`, `usage-YYYY-MM-<os>` (one per boot), `health-YYYY-MM`.

## Links

**Wikilinks for every cross-reference:** `[[note-name]]`. Obsidian and graphify both traverse them;
a markdown path link is invisible to the graph.

Link liberally. A `[[link]]` to a note that doesn't exist yet is not an error, it marks something
worth writing, **provided it is listed in [[Forward-Links]]**. An unlisted unresolved link is a bug,
and `brain-doctor` reports it.

**Never path-qualify a link** (`[[00-Meta/Conventions]]`): it breaks on every move. Basenames are
unique, so a plain `[[Conventions]]` always resolves. Link syntax quoted in prose, or in a commit
body (which `brain-commit` copies into the vault verbatim), goes in backticks.

## Reach

Every note is at most **2 hops** from [[00-MOC-Root]]; a record at most 3. `brain-doctor`'s
`reach` check enforces it. A new note goes into its folder's MOC when it is written:
`brain-compile` does this for the notes it creates, under an `Unsorted (brain-compile)` heading.

## Note shape

**One concept per note.** If a note needs two MOC entries, it is two notes.

A repository's page in `10-Repos/` is an index entry, not documentation: what the repo is, its
licence, its `checkout:` pointer, and a **"Known gaps — don't chase these"** section. That section
stops an agent re-investigating something already decided.

`checkout: <Remote-Name>` and `docs: <Remote-Name>/docs` are relative to `devRoot` in
`config.json`, so one note resolves on every machine. `brain-verify` fails on an absolute pointer
and on one into a cloned checkout that does not exist; a repo this machine never cloned is listed,
not failed.

## Where things live

| Content | Location |
|---|---|
| Repo-specific docs | the repo's own `docs/`: it **is** the repo's wiki page |
| Plans, all of them | `40-Plans/<YYYY-MM-DD>-<slug>/`: [[00-MOC-Plans]] |
| Reusable knowledge | `20-Knowledge/<Category>/`: [[00-MOC-Knowledge]] |
| People the owner knows | `20-Knowledge/People/<first-last>/<first-last>.md`, `type: person`, one folder each: [[00-MOC-People]] |
| Daily logs | `30-Sessions/YYYY/MM/YYYY-MM-DD.md`, split at the configured rollover hour |
| Decisions | `60-Decisions/Repos/<Remote-Name>/` · `60-Decisions/Identity/`: [[00-MOC-Decisions]] |
| Commit and usage records | `50-Ops/Commits/<YYYY-MM>/` + `commits-YYYY-MM.md` · `50-Ops/Usage/usage-YYYY-MM-<os>.md`: [[00-MOC-Ops]] |
| Attachments | `80-Assets/Images/` · `80-Assets/Diagrams/`: Obsidian's `attachmentFolderPath` |
| Repo brand assets | `80-Assets/Repos/<Remote-Name>/`: masters; the export ships in the repo |
| Unsorted | `90-Inbox/`: empty it, don't let it become an archive |

**Nothing is duplicated between the vault and a repo.** A repo's docs stay in the repo; the vault
links to them.

## Renaming a repository

Path-based ignores go stale on a rename, silently: Obsidian's `userIgnoreFilters` and
`.graphifyignore` just stop matching, and a graph shrinks with no error. After renaming a repo:

1. Rename its `10-Repos/<Remote-Name>/` folder and folder note, and `60-Decisions/Repos/<Remote-Name>/`,
   to the remote's exact casing; update the `checkout:` pointer (`brain-verify` fails on a dead one).
2. `bun --bun ~/.claude/hooks/brain-graph.mjs --force` and compare the node count. `--force` is
   needed because graphify refuses to shrink a graph without it.

On a case-insensitive filesystem a stale lowercase path resolves to the renamed folder and appears
to work. A wrong-but-working link is worse than a broken one.
